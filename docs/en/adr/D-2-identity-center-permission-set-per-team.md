## 1. Context

Without a gateway, the credential a person's tools send to Bedrock is the only place where identity, team and model rights can be attached (D-1). It must come from an Entra sign-in with MFA and a compliant device, name the person and the team in CloudTrail and CUR, and carry the team's model tier, without anything the user can set. IAM Identity Center is the AWS service for people's access to accounts, and the role session it creates has the user name as its session name. What remains to choose is how the team is attached to the session.

## 2. Decision drivers

| Driver | Source |
|---|---|
| Sign-in only through Entra, with MFA and a compliant device | 01 IAM-001 |
| Each call is charged to a team the platform assigns, and the user cannot change it | 01 CST-001, TEN-009 |
| Team membership comes from Entra groups and follows them | 01 IAM-004, TEN-004, TEN-007 |
| Per-team model tiers | 01 MDL-103 |
| Credentials expire within 1 hour; no long-term keys | 01 IAM-015, IAM-016 |
| CUR attributes cost to the caller's IAM principal; tags come from IAM users and roles, not session tags | [IAM principal cost allocation](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/iam-principal-cost-allocation.html) |
| Clients use the standard AWS SDK credential chain | 01 AS-27 |

## 3. Options considered

| Option | Drivers not met | Cost and effort | Risks | Outcome |
|---|---|---|---|---|
| 1. One permission set `LLM-Team-<team>` per team, assigned to the Entra group `llm-team-<team>` | — | One permission set per team, generated by CI from `teams.yaml` | IAM Identity Center quotas on permission sets (R-9); AWS Budgets actions cannot attach policies to Identity Center roles (R-13) | Chosen |
| 2. One permission set for everyone; the team from an Entra user attribute, passed as a session tag (attributes for access control) | CST-001 for people in several teams: one attribute holds one team; session tags do not reach CUR, so the team must be joined from a directory snapshot | One permission set; an HR-mastered attribute | The attribute must be kept in step with group membership by hand or by HR | Rejected; the fallback if option 1 hits the quotas |
| 3. One permission set that may only assume per-team IAM roles tagged `Team` and `CostCenter`; trust policies require the session name to equal the user name | — | Role chaining in every client profile; trust conditions on `sts:RoleSessionName` and `sts:SourceIdentity`; a user-name attribute in the session | More moving parts; chained sessions are limited to 1 hour; a mistake in a trust condition lets a user choose their session name and so their attribution | Rejected for now: its gain, native AWS Budgets actions per team, does not outweigh the complexity; revisit if the spend guard proves unreliable |
| 4. Long-term Bedrock API keys per person | IAM-015, IAM-016, CON-7 | — | — | Rejected (D-3) |

## 4. Decision

Each team gets one permission set, `LLM-Team-<team>`, assigned only to the team's Entra group on `llm-prod`, with 1-hour sessions and an inline policy generated from the team's tier. The role name carries the team and the session name carries the user, both set by AWS, so CloudTrail and CUR name the team and the person with nothing the user can change. A person in several teams has several permission sets and chooses one per session with `llm team`, which is the only choice they can make.

## 5. Consequences

| Kind | Consequence | Tracked in |
|---|---|---|
| Benefit | Team and person are attributed by AWS with no client field involved | V-7, V-15 |
| Benefit | Joiners, movers and leavers follow Entra groups through SCIM, with no sync job of ours | 01 TEN-004, TEN-007 |
| Cost | The number of permission sets grows with the number of teams | R-9 |
| Cost | AWS Budgets actions cannot target the Identity Center roles, so people's budgets need the spend guard | R-13; D-8 |
| Follow-up | Count the teams and confirm the group names | 01 Q-22; R-9 |
